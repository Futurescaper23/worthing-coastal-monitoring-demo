# Worthing Demonstrator Walkthrough

## Purpose

Use this six-screen walkthrough to introduce the public-data demonstrator clearly, without overstating what has been measured.

## Opening frame

This demonstrator shows how FutureScaping could structure a Worthing coastal monitoring interface using public evidence first, while leaving explicit placeholders for client-controlled post-works data.

State this early:

- the frontage shown is the public scheme context
- the current release is not an engineering assessment
- the current release does not claim measured post-repair change
- the July 2026 UAV baseline is still missing and must stay visibly labelled

## Recommended screen order

### 1. Scheme Overview

Show:

- the whole frontage from Sea View Road to Brooklands
- the ten public work areas
- the chosen proof location near Worthing Pier
- dataset readiness and source coverage

Say:

- this is the project framing screen
- it shows where public evidence is already strong
- it also makes the missing client baseline obvious

### 2. Work Area Detail

Show:

- the Pier East proof area
- the nearby repaired frontage context
- the currently available public evidence cards
- the caution that profile-to-groyne alignment is not yet engineering-verified

Say:

- this is the level where a client conversation becomes concrete
- we can already show a recognisable place and supporting public context
- we are still avoiding any claim about exact repaired assets until IDs are supplied

### 3. Historical Profiles

Show:

- the available CCO profile traces
- gain/loss colouring with blue for accretion and red for erosion
- the chart annotation that these are historical public-profile proxies

Say:

- this screen demonstrates the analytical method
- it shows how beach-shape history can be communicated visually
- it does not claim that post-repair beach performance has already been measured

### 4. Environmental Timeline

Show:

- survey dates
- relevant public storm or forcing context
- timeline joins between observations and available environmental records

Say:

- this is the evidence-timing screen
- it helps explain what was happening around each public survey window
- it is contextual rather than determinative

### 5. Bay Status

Show:

- readiness flags
- missing threshold warnings
- the required placeholder label:
  - `July 2026 UAV baseline — client data required.`

Say:

- this screen is intentionally honest
- it is a decision-support mock-up, not a live intervention engine
- it becomes substantially more powerful when client thresholds and post-works data arrive

### 6. Provenance and Uncertainty

Show:

- every source used
- dates, licences and limitations
- non-claims and missing layers

Say:

- this is what makes the demonstrator trustworthy
- every visible statement can be traced to a source
- every unsupported claim is deliberately excluded

## Close

End with the specific client ask:

1. July 2026 UAV baseline and metadata
2. exact repaired groyne IDs and repair types
3. latest profiles used operationally
4. design thresholds or target profiles
5. any permitted as-built or licence drawings needed for proof alignment

## Success test for the meeting

The walkthrough has worked if the client leaves feeling:

- the interface is credible and recognisably FutureScaping
- the public-data foundation is already useful
- the missing client datasets are clear and reasonable
- the next step is to supply data, not debate whether the product shape makes sense
